# Module 06b project ticket — bring to Module 7 kickoff

**Candidate story (proposed by Adam; not a merged-team agreement):** Anke Reuter, the maintenance-data coordinator at Kortmann's Gütersloh plant, needs to decide which machines should be checked for overdue calibration before the next production shift. Vendor records are inconsistent and acquire new JSON fields over time, so the team cannot easily rank machines by urgency. **First query:** “Which active Gütersloh machines have a calibration due date in the next 30 days or already overdue, ordered by due date?” A testable SQL starting point is: `SELECT name, json_extract(meta, '$.calibration_due') AS due FROM device WHERE site = ? AND json_extract(meta, '$.calibration_due') <= ? ORDER BY due;` with bound values for the site and 30-day cutoff. **Data source:** reproducibly generated synthetic machine, site and vendor-JSON data derived from the patterns in Modules 4 and 6b, with a declared fixed random seed; do not include real employee or production records. A minimal Datasette interface can show the query. A future project must add a relational `site` reference and foreign key, `CHECK(json_valid(meta))`, a trigger/generated column, replay-safe UPSERT loader, and before/after `EXPLAIN QUERY PLAN` plus timing and an injection self-test.

**Why this fits the professor's Module 7 checklist:** named person and workplace; decision changed by data; a specific first parameterized query; source that can be generated repeatedly. It reuses Modules 2–4 and 6b, and can optionally add a 6a analytical report.
